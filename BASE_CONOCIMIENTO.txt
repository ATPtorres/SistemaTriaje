BASE DE CONOCIMIENTO DEL PROTOTIPO DE TRIAJE — versión 4

FUENTE EJECUTABLE
  knowledge/triage_rules.json
  Este archivo TXT es documentación, no una segunda copia de las reglas.
  TRIAGE_KNOWLEDGE_PATH permite seleccionar otro JSON revisado.

ORIGEN Y ALCANCE
  Los criterios se migraron del motor local en el commit 0a81337.
  Se conservaron sus umbrales y niveles para verificar regresiones.
  Esto no acredita su corrección médica ni constituye ESI/MTS/CTAS/ATS oficiales.
  Los indicadores difuso y multifactorial son auxiliares y no deciden el nivel.

ESTRUCTURA DEL JSON
  version: versión semántica del conocimiento, independiente del código.
  fuente: procedencia documentada de las reglas.
  reglas: condiciones, conclusión, efectos, nivel opcional, peso y prioridad.
  agregaciones: conteos de hechos derivados verdaderos, sin duplicar fuentes.
  salidas: color y recomendación de las cinco prioridades locales.
  respaldo: regla explícita de nivel 5 si no se activa ningún criterio decisivo.

INFERENCIA
  Las entradas se validan con DatosPaciente. No se inventan signos vitales.
  Las reglas pueden afirmar hechos nuevos que activan otras reglas.
  Se evalúa hasta punto fijo: cada regla se activa una sola vez por evaluación.
  Los efectos solo afirman True; las dependencias derivadas son monótonas.
  Los ciclos sin hechos iniciales no se activan; no hay bucles infinitos.
  Se selecciona el menor nivel propuesto (mayor urgencia). El peso no puede
  hacer que una regla menos urgente desplace una de mayor urgencia.
  Prioridad e ID ordenan la ejecución y la traza; no cambian esta política.
  Los pesos se propagan por mínimo en las cadenas; no son probabilidades.

TRAZABILIDAD
  La clasificación, el motivo y WHY/HOW/TRACE provienen de la misma ejecución.
  Se guardan hechos, procedencia, reglas decisivas, versión, SHA-256 del
  contenido normalizado y snapshot completo del conocimiento.
  El snapshot permite reproducir el resultado aunque después cambie el JSON.
  El árbol de /decision-tree es un catálogo generado de las reglas actuales,
  no una representación de un protocolo clínico independiente.

EDICIÓN Y PRUEBAS
  Revisar cambios en Git y aumentar version; desplegar el JSON de forma atómica.
  No editar en paralelo el archivo utilizado por una evaluación en curso.
  No se ofrecen escrituras de reglas por HTTP: la API aún no tiene autenticación.
  Un archivo inválido o ausente bloquea el arranque y las nuevas clasificaciones.
  Ejecutar: python -m pytest -q
  Ejecutar: python clinical_validation.py --cases tests/fixtures/triage_regression.json
  Ver README.md y VALIDACION_CLINICA.md para alcance y limitaciones.
